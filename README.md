# Wishlists Service

[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)
[![Python](https://img.shields.io/badge/Language-Python-blue.svg)](https://python.org/)
[![Build Status](https://github.com/CSCI-GA-2820-FA26-001/wishlists/actions/workflows/ci.yml/badge.svg)](https://github.com/CSCI-GA-2820-FA26-001/wishlists/actions)
[![codecov](https://codecov.io/gh/CSCI-GA-2820-FA26-001/wishlists/graph/badge.svg)](https://codecov.io/gh/CSCI-GA-2820-FA26-001/wishlists)

A RESTful microservice for managing customer wishlists. A customer can have many wishlists, and each wishlist holds the products the customer may want to buy later.

## Overview

The service is a Python [Flask](https://flask.palletsprojects.com/) app backed by PostgreSQL through [Flask-SQLAlchemy](https://flask-sqlalchemy.palletsprojects.com/). It has two resources:

- **Wishlist**: a named list that belongs to a customer
- **Item**: a product saved in a wishlist (a subordinate resource under `/wishlists/<id>/items`)

All requests and responses use JSON.

## Data Model

### Wishlist

| Field         | Type    | Required | Notes                                                      |
| ------------- | ------- | -------- | ---------------------------------------------------------- |
| `id`          | integer | -        | Generated by the database                                  |
| `name`        | string  | yes      | Non-empty, up to 64 characters                             |
| `customer_id` | integer | yes      | The customer who owns the wishlist                         |
| `note`        | string  | no       | Up to 256 characters                                       |
| `items`       | array   | -        | Read-only in responses; manage items with the item endpoints |

A customer can't have two wishlists with the same `name`. Different customers can reuse the same name.

### Item

| Field         | Type    | Required | Notes                                         |
| ------------- | ------- | -------- | --------------------------------------------- |
| `id`          | integer | -        | Generated by the database                     |
| `wishlist_id` | integer | -        | Taken from the URL, not the request body      |
| `product_id`  | integer | yes      | The product being saved                       |
| `quantity`    | integer | no       | Must be at least 1; defaults to `1`           |
| `note`        | string  | no       | Up to 256 characters                          |

Deleting a wishlist also deletes all of its items.

## API Endpoints

| Method   | URL                             | Description                    | Success          |
| -------- | ------------------------------- | ------------------------------ | ---------------- |
| `GET`    | `/`                             | Admin UI (HTML page)           | `200 OK`         |
| `GET`    | `/health`                       | Service health status          | `200 OK`         |
| `POST`   | `/wishlists`                    | Create a wishlist              | `201 Created`    |
| `GET`    | `/wishlists`                    | List or filter wishlists       | `200 OK`         |
| `GET`    | `/wishlists/<id>`               | Read a wishlist and its items  | `200 OK`         |
| `PUT`    | `/wishlists/<id>`               | Update a wishlist              | `200 OK`         |
| `PUT`    | `/wishlists/<id>/clear`         | Clear all items from a wishlist | `200 OK`        |
| `DELETE` | `/wishlists/<id>`               | Delete a wishlist and its items | `204 No Content` |
| `POST`   | `/wishlists/<id>/items`         | Add a product to a wishlist    | `201 Created`    |
| `GET`    | `/wishlists/<id>/items`         | List or filter the products in a wishlist | `200 OK` |
| `GET`    | `/wishlists/<id>/items/<item_id>` | Read a product in a wishlist | `200 OK`         |
| `PUT`    | `/wishlists/<id>/items/<item_id>` | Update a product in a wishlist | `200 OK`       |
| `DELETE` | `/wishlists/<id>/items/<item_id>` | Delete a product from a wishlist | `204 No Content` |

### Health check

`GET /health` returns `200 OK` with `Content-Type: application/json` and the JSON body `{"status":"OK"}` when the service is responding.

### Create a wishlist

```http
POST /wishlists
Content-Type: application/json

{
  "name": "Birthday",
  "customer_id": 1001,
  "note": "Ideas for my birthday"
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "name": "Birthday",
  "customer_id": 1001,
  "note": "Ideas for my birthday",
  "items": []
}
```

The response also includes a `Location` header with the new wishlist's URL, for example `Location: http://localhost:8080/wishlists/1`.

Errors: `400` if `name` or `customer_id` is missing or the wrong type, `409` if the customer already has a wishlist with that name, `415` if the body isn't JSON.

### List wishlists

`GET /wishlists` returns a JSON array of every wishlist, each with its items. It returns `[]` when there are none.

To list the wishlists belonging to one customer, supply a `customer_id` query parameter:

```http
GET /wishlists?customer_id=1001
```

The response is `200 OK` with a JSON array of only that customer's wishlists, including their items.
If the customer has no wishlists, the response is `200 OK` with `[]`.

Only one integer `customer_id` query parameter is accepted per request. Empty, non-integer, comma-separated,
or repeated values return `400 Bad Request` using the standard JSON error response.
Requests without a `customer_id` filter continue to return all wishlists.
Filtering does not change any stored wishlists or items.

### Read a wishlist

`GET /wishlists/<id>` returns the wishlist with its items. Returns `404` if the wishlist doesn't exist.

### Update a wishlist

```http
PUT /wishlists/1
Content-Type: application/json

{
  "name": "Birthday 2026",
  "customer_id": 1001,
  "note": "Updated ideas"
}
```

This replaces the whole wishlist, so send every field you want to keep (`name` and `customer_id` are required). Fields you leave out, such as `note`, are cleared. Items are not changed. Returns `200 OK` with the updated wishlist.

Errors: `400` for missing or invalid fields, or if `customer_id` is different from the wishlist's current owner (the owner can't be changed), `404` if the wishlist doesn't exist, `409` if the customer already has another wishlist with that name, `415` if the body isn't JSON.

### Clear all items from a wishlist

```http
PUT /wishlists/1/clear
```

No request body is required. This removes only the items in the selected wishlist, keeping the wishlist and its existing `id`, `name`, `customer_id`, and `note` unchanged. Other wishlists and their items are not affected.

Response `200 OK` with the wishlist JSON and `items: []`:

```json
{
  "id": 1,
  "name": "Birthday",
  "customer_id": 1001,
  "note": "Ideas for my birthday",
  "items": []
}
```

Clearing an empty wishlist also returns `200 OK` with the unchanged wishlist JSON.

Errors: `404` with a JSON error response if the wishlist doesn't exist.

### Delete a wishlist

`DELETE /wishlists/<id>` deletes the wishlist and all of its items. It returns `204 No Content` with an empty body, even if the wishlist didn't exist.

### Add a product to a wishlist

```http
POST /wishlists/1/items
Content-Type: application/json

{
  "product_id": 2001,
  "quantity": 2,
  "note": "Size M"
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "wishlist_id": 1,
  "product_id": 2001,
  "quantity": 2,
  "note": "Size M"
}
```

`quantity` and `note` are optional. Any `wishlist_id` in the body is ignored; the one in the URL is used.

Errors: `400` if the body isn't a JSON object, `product_id` is missing or not an integer, `quantity` is not an integer of at least 1, or `note` is not a string of at most 256 characters, `404` if the wishlist doesn't exist, `415` if the body isn't JSON.

### List the products in a wishlist

`GET /wishlists/<id>/items` returns a JSON array of the wishlist's items, sorted by item `id`. It returns `[]` when the wishlist has no items, and `404` if the wishlist doesn't exist.

To check whether a product is already saved in a wishlist, supply a `product_id` query parameter:

```http
GET /wishlists/1/items?product_id=2001
```

The response is `200 OK` with a JSON array of only the items for that product in this wishlist, sorted by item `id`.
If the product isn't in this wishlist (even if it is saved in another one), the response is `200 OK` with `[]`.

Only one integer `product_id` query parameter is accepted per request. Empty, non-integer, comma-separated,
or repeated values return `400 Bad Request` using the standard JSON error response.
Requests without a `product_id` filter continue to return all items in the wishlist.

### Read a product in a wishlist

`GET /wishlists/<id>/items/<item_id>` returns a single item as JSON. Returns `404` if the wishlist doesn't exist, if the item doesn't exist, or if the item belongs to a different wishlist.

### Update a product in a wishlist

```http
PUT /wishlists/1/items/1
Content-Type: application/json

{
  "product_id": 2001,
  "quantity": 3,
  "note": "Size L"
}
```

Response `200 OK`:

```json
{
  "id": 1,
  "wishlist_id": 1,
  "product_id": 2001,
  "quantity": 3,
  "note": "Size L"
}
```

This replaces the item's fields, so send every field you want to keep (`product_id` and `quantity` are required). If you leave out `note`, it is cleared. The item's `id` and its wishlist don't change, and any `wishlist_id` in the body is ignored.

Errors: `400` if `product_id` is missing or not an integer, `quantity` is missing or not an integer of at least 1, or `note` is not a string of at most 256 characters, `404` if the wishlist doesn't exist, if the item doesn't exist, or if the item belongs to a different wishlist, `415` if the body isn't JSON.

### Delete a product from a wishlist

`DELETE /wishlists/<id>/items/<item_id>` removes the item from the wishlist. The wishlist itself is kept. It returns `204 No Content` with an empty body, even if the item didn't exist, so deleting twice is safe. An item that belongs to a different wishlist is never deleted.

### Root URL (admin UI)

`GET /` serves a single-page admin UI for eCommerce managers. From it you can create, retrieve, update, and delete a wishlist, search wishlists by customer ID (a name typed in the form narrows the results), and clear all items from a wishlist. The page calls the REST API above, and its files live in `service/static/`.

### Errors

Every error response is JSON with the same shape:

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "404 Not Found: Wishlist with id '42' was not found."
}
```

## Running the Service

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- [Visual Studio Code](https://code.visualstudio.com/) with the [Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers) extension

### Open the development environment

1. Clone the repository and open the folder in VS Code.
2. When prompted, choose **Reopen in Container** (or run **Dev Containers: Reopen in Container** from the Command Palette).

The dev container includes Python 3.12, all dependencies, and a PostgreSQL database. Run the commands below in the VS Code terminal inside the container.

### Start the service

```bash
make run
```

`make run` runs `honcho start`, which starts the service with gunicorn using the `Procfile`. The service listens on port `8080`. Try it out:

```bash
curl -i http://localhost:8080/wishlists
curl -i -X POST http://localhost:8080/wishlists \
  -H "Content-Type: application/json" \
  -d '{"name": "Birthday", "customer_id": 1001}'
```

## Testing

```bash
make test   # run the unit tests with coverage (must be at least 95%)
make lint   # run flake8 and pylint
```

Run a single test file with:

```bash
pytest tests/test_routes.py -v --no-cov
```

`--no-cov` turns off the coverage check. Without it, the run fails because one test file alone doesn't reach the 95% coverage that `setup.cfg` requires, even when every test passes.

> **Note:** The tests use the same database as `make run`, and they clear the tables before each test. Any wishlists you created with `curl` will be deleted when you run the tests.

The tests use the PostgreSQL database in the dev container. If you see `failed to resolve host 'postgres'`, the database container has stopped. Start it again from your computer's terminal:

```bash
docker start wishlists_devcontainer-postgres-1
```

## Deploying to Kubernetes

The service can run on a local [K3S](https://k3s.io/) cluster created with [k3d](https://k3d.io/) inside the dev container. Run these commands in the VS Code terminal:

```bash
make cluster   # create the nyu-devops cluster with a local registry and ingress on port 8080
make build     # build the cluster-registry:5000/wishlists:1.0 image from the Dockerfile
make push      # push the image to the cluster registry
make deploy    # create the database Secret if needed and apply everything in k8s/
```

`make deploy` creates the `wishlists-postgres-secret` Secret with a random password the first time it runs and reuses it afterwards. It then deploys PostgreSQL as a StatefulSet (see [k8s/postgres/README.md](k8s/postgres/README.md)) and the service as a Deployment. The service waits for PostgreSQL to be ready before it starts, and connects to it through the `wishlists-postgres` Service.

Check that everything is running, then call the service through the ingress:

```bash
kubectl get pods
curl -i http://localhost:8080/health
```

When both Pods are `Running` and `1/1` Ready, `/health` returns `200 OK` with `{"status":"OK"}`.

Remove the cluster with `make cluster-rm`. If `make push` fails with `no such host` for `cluster-registry`, add the registry to `/etc/hosts` (the dev container normally does this when it is created):

```bash
sudo bash -c "echo '127.0.0.1    cluster-registry' >> /etc/hosts"
```

## Browser test environment (issue #50)

The professor's [project template](https://github.com/nyu-devops/project-template)
is the starting point; its [Fall 2026 BDD lab](https://github.com/nyu-devops/lab-flask-bdd/tree/17456674f18e5352e2354bebd1f1dda569752ffe)
provides the BDD-specific setup. This branch follows that lab's
[Pipfile](https://github.com/nyu-devops/lab-flask-bdd/blob/17456674f18e5352e2354bebd1f1dda569752ffe/Pipfile):
Behave `~=1.3.3`, Selenium `==4.16.0`, requests `~=2.32.5`, and compare3 `~=1.0.4`.
Selenium 4.16.0 is the lab's explicit pin, not 4.6.

The development image is `quay.io/rofrano/pipeline-selenium:sp26`, as used by the
lab's [BDD workflow](https://github.com/nyu-devops/lab-flask-bdd/blob/17456674f18e5352e2354bebd1f1dda569752ffe/.github/workflows/bdd-tests.yml).
The lab's own devcontainer uses the same `sp26` tag from Docker Hub. Cucumber
autocomplete is already enabled in `devcontainer.json`.

1. Open this working copy in VS Code and run **Dev Containers: Rebuild Container**.
   Reopening an old container does not apply the new base image or dependencies.
2. In the rebuilt container, run `make run` and wait for the service to start.
3. In a second terminal in the same container, run `behave --tags=@setup --no-capture`.

Expect one passing scenario. Selenium opens the running Wishlist home page at
`http://localhost:8080/` and checks that its title contains `Wishlist Admin`.
The browser closes after the run, including when a scenario or browser configuration fails.

The hooks follow the lab's [browser environment](https://github.com/nyu-devops/lab-flask-bdd/blob/17456674f18e5352e2354bebd1f1dda569752ffe/features/environment.py):
`BASE_URL` defaults to `http://localhost:8080`, `DRIVER` to `chrome`, and
`WAIT_SECONDS` to `30`. The devcontainer sets `WAIT_SECONDS=5`, matching the lab.
Steps use `context.driver`, `context.base_url`, and `context.wait_seconds`.
To override the defaults or use the bundled Firefox alternative:

```bash
WAIT_SECONDS=20 behave --tags=@setup
DRIVER=firefox behave --tags=@setup
```

The hooks register browser cleanup immediately after launch. Outside the container,
install the locked dependencies with `pipenv sync --dev` and provide a compatible
browser and driver before running `pipenv run behave --tags=@setup`.

Create and Retrieve browser scenarios belong in their respective UI stories.
Reuse `features/steps/web_steps.py` for browser actions and UI assertions. For
scenarios that need existing wishlists, add `Given the following wishlists` to
the `Background` with `name` and `customer_id` columns and an optional `note`.
Like the lab, this step deletes all existing wishlists and then creates the
table's rows through the REST API, so every scenario starts from the same data.
Run Behave against a test or development instance, never a database with real data. Perform scenario actions and assertions through Selenium and
the Admin UI. The Tekton BDD task will run the feature scenarios after deployment.

## Project Structure

```text
Dockerfile                 - production image for the service
k8s/                       - Kubernetes manifests applied by make deploy
├── deployment.yaml        - service Deployment with /health probes
├── service.yaml           - ClusterIP Service on port 8080
├── ingress.yaml           - ingress routing / to the service
└── postgres/              - PostgreSQL StatefulSet and Service

service/                   - service Python package
├── __init__.py            - app factory
├── config.py              - configuration parameters
├── routes.py              - REST API routes
├── models/                - database models
│   ├── persistent_base.py - shared create/update/delete/find methods
│   ├── wishlist.py        - Wishlist model
│   ├── item.py            - Item model
│   └── item_query.py      - product_id filter for listing items
└── common/                - common code
    ├── cli_commands.py    - Flask command to recreate all tables
    ├── error_handlers.py  - JSON error responses
    ├── log_handlers.py    - logging setup
    └── status.py          - HTTP status constants

tests/                     - test suites
├── factories.py           - factories for fake test data
├── test_cli_commands.py   - CLI tests
├── test_error_handlers.py - error handler tests
├── test_wishlist.py       - Wishlist model tests
├── test_wishlist_clear.py - Wishlist clear action API tests
├── test_item.py           - Item model tests
├── test_item_query.py     - product_id filter API tests
└── test_routes.py         - REST API tests
```
